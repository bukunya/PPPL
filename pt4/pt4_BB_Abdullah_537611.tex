\section{Dasar Teori}
Mockito adalah sebuah framework mocking open-source yang sangat populer dan banyak digunakan untuk aplikasi berbasis Java. Framework ini memungkinkan pengembang perangkat lunak untuk membuat objek mock, yaitu objek tiruan yang meniru perilaku dari objek aslinya secara terkontrol. Dengan mengganti dependensi asli menggunakan mock, Mockito memungkinkan pengujian kode secara terisolasi tanpa perlu mengeksekusi metode aslinya secara langsung. Hal ini sangat membantu dalam menulis pengujian unit (unit test) yang bersih, mudah dipelihara, dan dapat diandalkan. Instalasi framework ini ke dalam proyek dapat dilakukan dengan menambahkan dependensi mockito-core melalui perangkat manajemen proyek seperti Apache Maven.

Terdapat beberapa konsep inti dalam penggunaan Mockito pada pengujian perangkat lunak:
\begin{enumerate}
    \item Mock Objects (Objek Tiruan): Mock objects adalah implementasi palsu dari objek nyata yang menyimulasikan perilakunya untuk tujuan pengujian. Objek ini memungkinkan suatu kelas diuji secara terisolasi dengan mengganti dependensinya menjadi versi yang sepenuhnya dapat dikontrol dan diprediksi.
    \item Stubbing: Stubbing adalah proses mendefinisikan apa yang harus dikembalikan oleh objek mock ketika sebuah metode spesifik dipanggil. Proses ini digunakan untuk menyimulasikan berbagai skenario, seperti mengembalikan nilai tetap, melempar eksepsi (exception), atau meniru respons sistem yang lambat. Implementasinya sering menggunakan sintaks when(...).thenReturn(...).
    \item Verification (Verifikasi): Verifikasi adalah proses untuk memeriksa apakah metode-metode tertentu benar-benar dipanggil pada objek mock selama eksekusi pengujian. Langkah ini memastikan bahwa kode yang diuji berinteraksi dengan dependensinya persis seperti yang diharapkan, contohnya memastikan sebuah metode dipanggil dengan argumen spesifik dalam jumlah waktu tertentu menggunakan fungsi verify(...).
\end{enumerate}

public class Book {

public interface LibraryModel {
    boolean isBookAvailable(String id);

    void peminjaman(String title, String username);

Kode diatas merupakan interface LibraryModel yang memiliki tiga method yaitu isBookAvailable untuk mengecek ketersediaan buku berdasarkan id, peminjaman untuk melakukan peminjaman buku berdasarkan judul dan username, serta getAllBooks untuk mendapatkan daftar semua buku yang tersedia.

\subsection{LibraryControl}
\begin{lstlisting}[style=javastyle, caption={LibraryControl.java}]
package org.example;

public class LibraryControl {
    private LibraryModel bookModel;
    private NotificationService notificationService;

    public LibraryControl(LibraryModel bookModel, NotificationService notificationService) {
        this.bookModel = bookModel;
        this.notificationService = notificationService;
    }

    public boolean checkAvailability(String id) {
        return bookModel.isBookAvailable(id);
    }

    public void borrowBook(String id, String title, String username) {
        bookModel.getAllBooks();

        if (bookModel.isBookAvailable(id)) {
            bookModel.peminjaman(title, username);
            notificationService.sendNotification(username, title);
        }
    }
}
\end{lstlisting}

Kode diatas merupakan kelas LibraryControl yang memiliki dua atribut yaitu bookModel dan notificationService. Kelas ini juga memiliki konstruktor untuk menginisialisasi atribut-atribut tersebut. Kelas ini memiliki dua method yaitu checkAvailability untuk mengecek ketersediaan buku berdasarkan id dan borrowBook untuk melakukan peminjaman buku berdasarkan id, judul, dan username. Pada method borrowBook, pertama-tama akan memanggil method getAllBooks untuk mendapatkan daftar semua buku yang tersedia. Kemudian akan mengecek ketersediaan buku menggunakan method isBookAvailable. Jika buku tersedia, maka akan melakukan peminjaman menggunakan method peminjaman dan mengirimkan notifikasi menggunakan method sendNotification.

\subsection{LibraryControlTest.java}
\begin{lstlisting}[style=javastyle, caption={LibraryControlTest.java}]
package org.example;

import org.junit.jupiter.api.BeforeEach;
import org.junit.jupiter.api.DisplayName;
import org.junit.jupiter.api.Test;
import org.mockito.InOrder;
import org.mockito.Mockito;

import static org.junit.jupiter.api.Assertions.assertFalse;
import static org.junit.jupiter.api.Assertions.assertTrue;
import static org.mockito.ArgumentMatchers.anyString;
import static org.mockito.Mockito.*;

class LibraryControlTest {

    private LibraryModel bookModel;
    private NotificationService notificationService;
    private LibraryControl control;

    @BeforeEach
    void setUp() {
        bookModel = Mockito.mock(LibraryModel.class);
        notificationService = Mockito.mock(NotificationService.class);
        control = new LibraryControl(bookModel, notificationService);
    }

    @Test
    @DisplayName("Cek ketersediaan buku mengembalikan nilai dari model")
    void testCheckAvailability() {
        when(bookModel.isBookAvailable("B001")).thenReturn(true);
        when(bookModel.isBookAvailable("B002")).thenReturn(false);

        assertTrue(control.checkAvailability("B001"));
        assertFalse(control.checkAvailability("B002"));
    }

    @Test
    @DisplayName("Apabila buku tidak dipinjam (tersedia), fungsi peminjaman dipanggil")
    void testBorrowBook_WhenAvailable_ShouldCallPeminjaman() {
        when(bookModel.isBookAvailable("B001")).thenReturn(true);
        control.borrowBook("B001", "Clean Code", "Afif");
        verify(bookModel, times(1)).peminjaman("Clean Code", "Afif");
    }

    @Test
    @DisplayName("Apabila buku sedang dipinjam (tidak tersedia), fungsi peminjaman TIDAK dipanggil")
    void testBorrowBook_WhenNotAvailable_ShouldNotCallPeminjaman() {
        when(bookModel.isBookAvailable("B001")).thenReturn(false);
        control.borrowBook("B001", "Clean Code", "Afif");
        verify(bookModel, never()).peminjaman(anyString(), anyString());
    }

    @Test
    @DisplayName("Verifikasi urutan eksekusi: getAllBooks -> peminjaman -> sendNotification")
    void testBorrowBook_ExecutionOrder() {
        when(bookModel.isBookAvailable("B001")).thenReturn(true);
        control.borrowBook("B001", "Clean Code", "Afif");
        InOrder inOrder = Mockito.inOrder(bookModel, notificationService);
        inOrder.verify(bookModel).getAllBooks();
        inOrder.verify(bookModel).peminjaman("Clean Code", "Afif");
        inOrder.verify(notificationService).sendNotification("Afif", "Clean Code");
    }
}
\end{lstlisting}

Kode diatas adalah kode testing utama yang menggunakan Mockito. Terdapat @BeforeEach yang digunakan untuk menginisialisasi objek-objek yang akan digunakan dalam testing. Kemudian terdapat beberapa test yang akan dibahas satu persatu.

\begin{enumerate}
    \item testCheckAvailability: Test ini digunakan untuk mengecek apakah fungsi checkAvailability mengembalikan nilai yang sesuai dengan yang diharapkan. Pada test ini, mahasiswa menggunakan when untuk menentukan nilai yang akan dikembalikan oleh method isBookAvailable pada bookModel. Kemudian mahasiswa menggunakan assertTrue dan assertFalse untuk memverifikasi hasil dari fungsi checkAvailability.\label{two}
    \item testBorrowBook\_WhenAvailable\_ShouldCallPeminjaman\: Test ini digunakan untuk mengecek apakah fungsi peminjaman dipanggil ketika buku tersedia. Pada test ini, mahasiswa menggunakan when untuk menentukan bahwa buku dengan id "B001" tersedia. Kemudian mahasiswa memanggil fungsi borrowBook dan menggunakan verify untuk memastikan bahwa fungsi peminjaman dipanggil dengan parameter yang sesuai.\label{three}
    \item testBorrowBook\_WhenNotAvailable\_ShouldNotCallPeminjaman\: Test ini digunakan untuk mengecek apakah fungsi peminjaman tidak dipanggil ketika buku tidak tersedia. Pada test ini, mahasiswa menggunakan when untuk menentukan bahwa buku dengan id "B001" tidak tersedia. Kemudian mahasiswa memanggil fungsi borrowBook dan menggunakan verify untuk memastikan bahwa fungsi peminjaman tidak dipanggil.\label{four}
    \item testBorrowBook\_ExecutionOrder\: Test ini digunakan untuk memverifikasi urutan eksekusi fungsi-fungsi yang dipanggil dalam fungsi borrowBook. Pada test ini, mahasiswa menggunakan InOrder untuk memverifikasi urutan eksekusi fungsi-fungsi yang dipanggil. mahasiswa memastikan bahwa fungsi getAllBooks dipanggil terlebih dahulu, kemudian fungsi peminjaman, dan terakhir fungsi sendNotification.\label{six}
\end{enumerate}

\subsection{Soal}
Implementasikan mockito, identifikasi stub dan mock yang bisa digunakan dalam kasus berikut. Silahkan menambahkan fungsi atau class yang dibutuhkan.
\begin{enumerate}
\item Tambahkan fungsi untuk cek ketersediaan buku pada controller dan model.. Cek ketersediaan buku berdasarkan id. Buatlah test method untuk method cek ketersediaan pada controller. Terjawab pada \ref{one} dan \ref{two}.
\item Meminjam buku (id buku). Buat 2 test scenario:
\begin{enumerate}
    \item Apabila tidak sedang dipinjam maka fungsi peminjaman buku akan dipanggil. Terjawab pada \ref{three}.
    \item Apabila buku sedang dipinjam, lakukan verifikasi bahwa fungsi peminjaman buku tidak dipanggil. Terjawab pada \ref{four}.
\end{enumerate}
\item Tambahkan class model notificationService yang akan mengirimkan notifikasi apabila buku berhasil dipinjam atau dikembalikan. Urutan proses yang diharapkan (eksplor penggunaan fungsi InOrder untuk memastikan urutan pemanggilannya sesuai):
\begin{enumerate}
    \item getAllBooks()
    \item Peminjaman(title, username)
    \item sendNotification(username, title)
\end{enumerate}
Terjawab pada \ref{five} dan \ref{six}.
\end{enumerate}

\section{Kesimpulan}
Berdasarkan praktikum yang telah dilaksanakan, dapat ditarik beberapa kesimpulan sebagai berikut:
\begin{enumerate}
    \item Framework Mockito terbukti sangat efektif dalam melakukan pengujian unit (unit testing) dengan mengisolasi kelas yang diuji (LibraryControl) dari antarmuka dependensinya (LibraryModel dan NotificationService). Hal ini membuat pengujian menjadi lebih fokus pada logika bisnis tanpa bergantung pada implementasi infrastruktur asli.
    \item Penggunaan teknik stubbing melalui metode when(...).thenReturn(...) memungkinkan penguji untuk merekayasa skenario pengujian dengan mudah, seperti menyimulasikan kondisi di mana buku tersedia atau tidak tersedia, tanpa memerlukan modifikasi pada basis data nyata.
    \item Verifikasi interaksi (behavior verification) berhasil diimplementasikan menggunakan fungsi verify(). Fungsi ini memastikan bahwa metode tertentu dipanggil sesuai skenario, baik dipanggil tepat satu kali maupun tidak dipanggil sama sekali (never()).
    \item Fitur InOrder pada Mockito terbukti sangat handal untuk memastikan kebenaran alur program secara ketat dengan memvalidasi urutan eksekusi pemanggilan metode. Pada kasus ini, urutan proses sistem yaitu getAllBooks() $\rightarrow$ peminjaman() $\rightarrow$ sendNotification() berhasil diverifikasi dengan tepat.
\end{enumerate}
